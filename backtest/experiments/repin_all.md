## Which column each existing pin actually matches

Pin conventions were never uniform. This says, per field, which
column the existing value reproduces - so the new convention below is
a deliberate choice, not an accident inherited from one bad day.

| pin field | matches `is` | matches `oos` | matches `all` | matches nothing |
|---|---:|---:|---:|---:|
| `n` | 17 | 0 | 0 | 37 |
| `net` | 16 | 0 | 0 | 38 |
| `dd_net` | 47 | 0 | 0 | 7 |
| `oos_n` | 0 | 20 | 0 | 34 |
| `oos_net` | 0 | 20 | 0 | 34 |
| `oos_dd_net` | 0 | 36 | 0 | 18 |

## The new convention these numbers will be written under

| field | span | lens |
|---|---|---|
| `n`, `net`, `wr_net` | IS dataset, 2023-01..2026-08 | net |
| `oos_n`, `oos_net`, `oos_wr_net` | OOS dataset, 2021-22 | net |
| `dd_net` | both eras merged, calendar order | net |
| `n_all`, `net_all` | both eras merged | net |
| `gross_win`, `oos_gross_win` | as `wr_net` but gross | gross |

Open trades are dropped everywhere, matching the lens. Some older pins
counted them, which is why a few `n` values are one higher than re-derived.

## Why the win rates differ

`gross_win` is the old `win`: the same trades counted before fees,
slippage and funding. `wr_net` is after them.
