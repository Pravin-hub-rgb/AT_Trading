## the rule, as stated by the owner

> "any book jisme IS ya OOS negative hai usko hata"
> "ek era mai negative hai toh hatana hai"

Applied literally: **`IS < 0` OR `OOS < 0`**. No exceptions, no thresholds.

## what was retired

**33 keys removed, 236 → 203.** The count is 33 rather than 32 because retiring a
book also retires any alias pointing at it (see the dangling-alias note below).

`registry/retired.py` holds the keys; `registry/__init__.py` subtracts them from
the merged dict. **The definitions stay in their family modules**, so any retired
book is one line to restore. That is the difference between retiring and
deleting.

### dangling alias — 1 key, not a book

`swingpause_cd0_single_sw10` is a str-valued row aliasing `swingpause_sig_sw10`,
which is retired above. `registry/helpers.py` raises `KeyError` when an alias
targets a missing book, so retiring the target alone would have **broken the
registry** the moment anything iterated it — the prune would have made things
worse. The alias is retired too, and `retired.py` asserts this pairing so the
file cannot be edited back into a state that breaks alias resolution.

## the archive — retired, not deleted

The owner was explicit about what "hatana" means:

> "ye book se hat rahi hai archive mai hongi he - jaise kabhi experiment karna ho
> toh waha kaam aaye harness ka code wagera"

So the requirement is not "remember the numbers", it is **be able to run it again**.
A markdown table of pins does not satisfy that; a retired book has to come back
with its parameter dict intact.

**No config was ever copied anywhere.** The definitions never left their family
modules — `registry/retired.py` holds keys, and `archived()` reads the live config
objects back out at call time. That means one source of truth, no snapshot to go
stale, and the harness code for every retired book still runs.

`exp_archive_list.py` writes `_archive_list.md`, `_archive_list.json` (every
retired book's full config and pins) and `docs/method/BOOK_ARCHIVE.md`.

**The one mismatch is recorded rather than smoothed over.** `trail_skipn4` out of

pin counted it. That is a boundary-trade convention, not a config problem — the
book is faithfully reproduced — but it is a real difference and it is why this was
run at all.

## verification

- `exp_registry_snapshot.py check` — PASS, 151 rows, re-anchored
- `exp_fastcheck.py` — PASS on all 7 surviving fsent books
- `exp_origin_lookahead.py` — PASS, no duplicate keys, every swing key builds
- `exp_resultsdb.py check` — PASS, registry, docs and queue agree
- `book()`, `shortlisted()`, `alias_of()` all still work; every key resolves

**One pre-existing issue, not caused by this change:** `_registry_before.json` was
already stale before the prune — it failed its own check on `HEAD`, with roughly
156 differing rows, because pins in it predated earlier work (it carries
`baseline_no_partial_sw10` at 502 / +238.45R where the registry has 506 /
+282.67R). Re-anchoring therefore baked in that pre-existing drift as well as the
prune. Flagged rather than hidden, because a re-anchored baseline that also
silently accepts 156 unrelated differences is not the same as a clean re-anchor.

**One bug in the harness itself, found while doing this and fixed:**
`exp_prune_list.py` originally attached the group label with
`v.setdefault("group", gname)`. `EXPERIMENTS` hands out references, not copies, so
that wrote a `group` key into every live config dict — anything importing the
registry in the same process would have seen a field that does not exist on disk.
It now finds the group without writing.

## restoring a retired book

Delete its key from `RETIRED` in `registry/retired.py`, fix the `assert` count, and
re-anchor the snapshot:

```
# remove the key from RETIRED
$env:PYTHONIOENCODING='utf-8'
python exp_registry_snapshot.py write _registry_before.json
python exp_registry_snapshot.py check _registry_before.json
```

The definition has not moved. Nothing needs to be re-derived, though
`exp_fastcheck.py <book>` will confirm the pins still reproduce.
